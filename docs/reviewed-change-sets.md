# Reviewed change sets

Open `:desired /absolute/path/to/manifests.yaml` or an explicitly configured `@source-profile.yaml`. Press `b` (or `:changeset` while in desired review) to open a retained change set. Opening or drawing this view does not invoke admission, a renderer, Git, or a persisted write.

1. Press `p` and explicitly confirm the server preview. The default button is Cancel. Eligible targets receive strict `dryRun=All` create or server-side apply requests using the same `k9plus-change-set` field manager as eventual execution. Force is never requested.
2. Review Plan, Changes, Ownership and Evidence. The plan shows captured context, source digest, namespace/kind selection, per-target UID/resourceVersion/generation or verified named absence, admission changes and omitted fields. Incomplete projections, excluded Secrets, denied reads, ambiguous ownership and cluster-scoped resources remain visible and cannot execute.
3. Space selects a row; `m` selects eligible rows. Press `a`, acknowledge unreviewed full-object fields and partial batch behavior, then explicitly Apply. Cancel is again the default. A context, namespace, originating view, plan or selection change rejects the old confirmation.
4. Outcomes retains per-target progress; `r` refreshes the receipt and `x` cancels remaining work. `:operations` retains the receipt after navigation. Esc returns through the retained source review with its source, query and selection. `o` opens a separate read-only native controller review; API acceptance or generic object observation does not assert workload readiness.

The collector follows exact native named references for ownership. A supported controller, tracking metadata or a possible managed-by marker routes toward source/controller review (`g`), with UID-verified ownership distinguished from copied or readable name-only associations. Missing, denied, malformed, omitted or unverified references block direct application. A complete bounded chain without supported markers is not proof that a resource is unmanaged. No repo path, source branch, controller action or Git mutation is inferred or run automatically.

Every persistent target rechecks the retained source fingerprints, exact live UID/resourceVersion/generation or verified absence, management metadata, bounded owner graph and named read/write permission. A local source changed during preflight blocks submission. Git sources retain the exact reviewed commit and payload; changing a checkout or branch tip does not silently substitute another commit. Plans expire after five minutes, including their preflight/write deadlines, and each eligible target is claimed once. The workflow does not prune, force field ownership, retry uncertain writes, or provide filesystem, ownership-graph or batch transaction isolation. Writes already submitted retain their captured clients and destination if navigation changes.

`ACCEPTED` is an API request fact. `OBSERVED` requires a separate bounded named GET that verifies the accepted UID/generation and admitted object fields; the receipt includes the independently observed resourceVersion, source and time. Runtime adoption, application health and controller completion remain separate. Failed permissions or stale preconditions do not submit a write. A canceled, timed-out, mismatched or unavailable observation after acceptance remains `UNKNOWN` while retaining accepted steps and the operation ID. Cancellation does not roll back earlier writes; a partial batch is not atomic.

Raw authored/admitted objects remain private. Secret objects are excluded before native lookup or admission; ConfigMap data/binaryData, confidential environment values and other sensitive projection fields do not cross plan or receipt text. Applying the complete authored object requires explicit acknowledgment of fields that the safe review cannot display. API diagnostics are classified without copying confidential request values into receipts.

The native Plan/table and detail tabs preserve identity, textual status, keyboard navigation, tab search/scroll and minimum-size guidance at 120/80/60 columns and a 40×16 terminal (40×12 content viewport). Verification covers deterministic native SimulationScreen frames, real client-go HTTP absence classification, captured named ownership reads, source/identity/expiry changes, confirmation guards, partial permissions, cancellation, uncertain writes and safe receipts. These are fixture and transport checks; they are not a live-cluster admission trial or operator study.
