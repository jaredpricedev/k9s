# Log workbench

Approved scope: implement all eleven requested logging improvements in k9+ and verify them in the existing iximiuz Kubernetes playground. Preserve the existing log shortcuts and make new controls discoverable in help. Changes remain on a reviewable feature branch.

The workbench uses entries independent of presentation: source namespace/pod UID/pod/container/restart generation, runtime timestamp, optional application timestamp, raw message, parsed fields and marker provenance. Never parse TUI markup. Bound every queue, line, multiline group, reorder buffer and recording; report loss and truncation visibly. Freeze selection by entry identity while streams update.

1. Parse JSON objects and logfmt per entry, with a per-source sample of up to fifty entries for format reporting. Mixed/malformed entries remain searchable raw text. Show time, level, message columns; expand full fields/original lines. Queries support field equality/inequality and numeric ordering, including nested dotted fields and semantic severity ordering. Missing fields do not satisfy comparisons, including inequality. Unstructured input supports raw regular expressions; reject invalid queries without replacing the last working query.
2. Consecutive identical entries may collapse with occurrence counts, preserving originals. A top-patterns view groups normalized templates, retaining level and HTTP status differences. Expand a pattern to its entries. Do not erase diagnostic numbers indiscriminately.
3. Stack negative substring exclusions, show active rules and hidden count, and persist a profile by cluster/context, namespace and workload app label. Support configurable app-label keys, with workload kind/name fallback. Read declarative team rules from annotation `k9plus.io/log-noise` as a JSON array of strings. No command evaluation. Local rules overlay team rules and can be cleared without changing Kubernetes resources.
4. Interleave source join/leave, restarts, ReplicaSet revisions and relevant Kubernetes Events. Marker timestamps and origin must remain distinguishable; Events may be delayed, aggregated, missing or forbidden. Use `lastState.terminated` when available, deduplicate boundedly, and keep logs usable without Event permission.
5. Workload logs follow a label selector with list/watch and relist recovery. Track source identity by pod UID/container/restart generation. Maintain per-source reconnect cursors, cancellation-safe reads and sends, bounded active streams, visible cap/loss notices. A single pod view follows that pod's container restarts; a workload view follows replacement pods.
6. Disk-backed JSONL recording with a bounded render ring, size and retention limits, private directory/files, paging older recorded entries, search over recording (ripgrep optional, typed filtering in Go), resume and export. Default recordings are redacted. Raw recording requires an explicit session action; toggling display redaction must not silently enable raw recording. Recording errors are visible and must not stop live logs.
7. Approximate timestamp merge uses a bounded reorder window and a short colored source gutter. Isolate or exclude a source and compare per-source lanes. Explain node clock skew in the UI.
8. Group source-local stack trace continuations with timeout, line and byte bounds. Expand on demand. Groups never cross pod UID/container/generation. Filtering considers the entire grouped entry.
9. A one-line lines/sec histogram shows maximum severity in buckets, observed and visible counts, and supports jumping to a bucket/spike. Counts include collapsed occurrences; define window as observed retained data.
10. Redact JWTs, bearer tokens, private-key blocks and AWS-shaped keys by default, including copy/export and persisted default recording. Toggle display redaction explicitly. Neutralize terminal escapes/control sequences and escape TUI text at rendering boundaries. Redaction is heuristic, not a guarantee of removal of all credentials.
11. Yank a selected entry or marked range with context, namespace, pod, container, runtime timestamps, active filters and loss/truncation context. Redacted by default.

Kubernetes constraints: content filtering is client-side; PodLogs has no seek. Timestamp requests always use timestamps=true. Node clocks make cross-pod ordering approximate. A server timestamp jump reconnects with sinceTime; local recorded history can be searched/paged independently. previous covers at most one available terminated container generation; node rotation caps history and the API serves the latest available file. Recording only preserves data actually observed by the client.

Validation: pure tests for malformed/mixed records, typed query semantics, pattern safety, multiline isolation and bounds, redaction across boundaries, recording retention/resume/search/export, histogram multiplicity and stable ordering. Fake Kubernetes tests for watch membership/restarts/cursors/cancellation and permissions. UI tests for actions and safe selection. Full Go suite and focused race tests. Live playground checks use dedicated logging-demo namespace; preserve existing Flux/cert-manager demos.
