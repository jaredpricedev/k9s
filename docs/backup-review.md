# Optional Velero backup review groundwork

Use `:backup-review <controller-namespace>` while an explicit application namespace and context are selected. This read-only native view reads one page (request 101, retain at most 100) each of Velero v1 Schedules, Backups and Restores in that controller namespace. Each read has a three-second timeout; collection has a ten-second deadline. No other context or namespace is scanned. Missing APIs and proxy 404s remain unknown, denied reads remain denied, and truncated pages remain partial. Empty records do not establish application protection.

Each record retains at most 32 values per include/exclude list and 256 bytes per string, with projection truncation marked partial. The fixed 300-record maximum also bounds total retained projection size. The view retains bounded declared fields, object UID/resourceVersion and capture/read times. Namespace/resource includes and excludes describe controller declarations; schedule labels and backupName references do not establish ownership. No raw objects, annotation values, credential configuration, Secret reads, CLI commands, agents, backup execution, restore execution or probes are retained or performed. Storage locations are not collected. The generic resource browser remains available for other providers without importing a provider adapter automatically.

Backup Completed does not establish recoverability. Restore Completed describes the controller workflow only; it establishes neither actual restore testing nor application health. Application restore-test evidence is Unreported because this collector has no independent test source. There is no global latest claim from a retained page.

Tab/Shift-Tab and 1–5 change tabs; `/` searches; `r` explicitly refreshes; `c` cancels collection; Esc returns. Tab search/scroll and captured evidence survive return, failed refresh and disconnection. Destination changes require reopening. A compact single pane supports 80×24 and 40×12; no color or icons are needed to understand coverage.

This is optional provider groundwork for issue #68, not completion of TK24. Human demand validation, supported Velero versions, CSI/operator adapters, real-cluster provider compatibility and independent application restore-test evidence remain open. Tests use synthetic API objects, a local HTTP server and native simulated terminal frames; they do not constitute live provider validation or an operator study.
