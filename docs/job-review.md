# Scheduled and selected Job review

Select a native `batch/v1` CronJob or Job, then run `:job-review` (also available in contextual Actions). The review captures the current context, namespace, name and UID before bounded reads. It keeps the resulting evidence until an explicit `r` refresh; a refresh failure retains the original source, capture time, query, tab, selected identity and scroll.

Use 1–5 or Tab for Overview, Runs, Pods, Schedule and Evidence. `j`/`k` selects retained Runs or Pods. Enter opens supporting investigation; `v` shows exact retained selected evidence. On Pods, `l` opens logs only after a fresh identity check. An empty Pod tab cannot silently substitute the parent Job as the selection.

`o` checks the captured source identity, then opens its existing native actions. CronJob `t` triggers and `s` suspends/resumes through existing confirmations and guarded operations. `:operations` reviews progress and the accepted Job identity. The review never submits a write or a hidden retry. Esc returns to the retained review; an owned namespace change is restored on return. A user destination change invalidates the old navigation/refresh client.

CronJob Schedule shows the retained expression, `spec.timeZone`, suspend, concurrency policy, starting/Job deadlines, history limits and last scheduled/successful API timestamps. It calculates three future matching times from the capture time with the maintained `github.com/robfig/cron/v3` standard parser and embedded IANA timezone data. This is a calculation, not a prediction of controller execution. Deadlines, concurrency, suspension and controller delay can prevent a matching run.

When `spec.timeZone` is absent, the actual controller timezone is unknown. The screen labels its UTC reference preview as incomplete. Nonexistent DST local times are skipped; repeated local times retain distinct offsets. Suspended preview times are explicitly conditional on resuming. Invalid zones/schedules remain unavailable, rather than using a guessed value.

Runs retain API creation/start/completion timestamps and the scheduled-timestamp annotation separately. Manual trigger annotations and controlling CronJob owner name/UID remain explicit source evidence. A selected Job does not automatically read its parent schedule. True terminal conditions establish failure/completion; failed Pod attempts alone do not establish a failed Job. Missing counts remain `?`, not measured zero.

Job and Pod reads stay in the captured namespace, with at most four pages of 200 candidates each and a hard 800-candidate limit even if a server ignores pagination. Controller owner references must match the native API and captured UID. The model keeps the newest 64 verified obtained Job records and at most 64 verified owned Pods. Retained lists can be incomplete due to permissions, TTL, history limits, deletion, pagination and local caps. **Missing retained Jobs alone never prove a missed execution.** Source times and full collection limits remain in Evidence. Raw object specs, environment values and Secret contents are not retained; declared images and runtime image IDs stay separate.

The view uses the common 40×12 available task minimum (40×16 compact terminal), narrow status/identity budgeting, monochrome text markers and resize restoration. Native fixture tests cover the supported frames, one size below minimum, timezone/DST boundaries, forbidden history, failed attempts/one-off outcomes, recreation, owner mismatches, local caps, query/scroll/return and changed destinations. These checks are not a live-cluster integration or operator study.
