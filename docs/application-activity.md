# Retained application activity

Create/use an explicit workspace for the application: choose context, namespaces, label selector and relevant kinds. Open `:activity` or tab `7`/Tab. The scope name, captured context and window start stay visible. Search filters retained entries locally with the workspace's normal `kind:`, `ns:`, `name:` and `status:` tokens.

Each workspace refresh records bounded current API projections in memory. First observations describe what was obtained when this window opened. Later entries compare meaningful fields across explicit observations: image declarations, runtime image IDs, workload revisions/readiness, controller revisions/reconciliation, Job conditions/outcomes, and schedule source changes. Capture time and API creation/condition/Job timestamps remain distinct. ResourceVersion churn alone does not produce activity. Missing source fields are unavailable values; they do not establish an unset field or measured zero.

Chart version, application version, Helm release revision, controller/source revision, declared container reference and resolved runtime image ID have separate labels. A tag remains an authored reference; a resolved image ID stays exact source evidence. Controller conditions with an older observed generation remain marked accordingly. Job failed Pod attempts and terminal failure/completion use the same typed source interpretation as Job review. Schedule matches are calculated separately by Job review, with timezone/DST/suspend/deadline assumptions and incomplete-history limits.

An explicit refresh while Activity is active also reads current retained core Events for at most 16 already obtained application resource UIDs, in their captured namespaces. It uses an exact UID field selector and checks source API/kind/namespace/name/UID locally. Events have their own labels, so the read uses the captured resource identity. Reads stay bounded by time, two 64-candidate pages per target and at most 128 retained Event records. Denied, unqueried, capped and missing access stays visible. Event UID/aggregate changes are deduplicated; API first/last/event/series times and counts remain source evidence. A returned current list cannot establish earlier or continuous Event history.

Enter/`v` shows exact retained evidence without a read. `i` opens supporting investigation for the captured resource UID (or an Event's regarding resource); a replacement cannot silently take its place. `J` opens native Job/CronJob review. Returning preserves scope, query, tab and event selection. The retained timeline has at most 512 entries, 2,000 tracked sources and a 24-hour window; pruning/caps expose omitted counts and boundaries. Reopening, scope binding changes and process restart start a new window. RBAC, TTL/history deletion, bounded lists and time between explicit refreshes leave gaps. Raw specs, environment values and Secret contents are excluded; recognizable credential text is redacted.

Verification uses typed model/dynamic fake/native-cell fixtures for meaningful changes, missing values, denied/partial/stale refresh, source replacements, bounds/restart, Event duplicates/aggregation, source navigation and supported terminal sizes. It does not claim a live-cluster integration, real PTY journey or operator study.
