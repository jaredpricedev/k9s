# Fork review — 2026-09-06

## Baseline and scope

Reviewed `jaredpricedev/k9s`, starting at `2d3ccc6ba2ce98c3781bfc441bb3e884f072774f`. The fork's default branch had no commits ahead of upstream and was 21 commits behind. The working branch incorporates upstream through `84852e6e47ae830b30c921ffa5838443387e096e` by fast-forward, preserving authorship/history. No existing branch was deleted or force-pushed.

Review covered fork divergence, dependency/build configuration, table/index/filter behavior, resource discovery, native action/read-only handling, Flux API integration, plugin execution and representative community plugins. New code received independent review. This is a scoped engineering review with executable regression evidence, not a guarantee that every existing defect or vulnerability has been found.

## Findings addressed

| Finding | Impact and change |
| --- | --- |
| Upstream fixes missing | Incorporates custom-resource Age/wide-column sorting, Kubernetes 1.31+ port-forward authorization, CRD discovery classification, plugin schema fixes and upstream dependency updates. |
| `RowEvents.At` accepted `index == length` | Could panic on an empty table or a selection past the end. Rejects this boundary. |
| Replacing a row left an old ID index | Old identifiers could resolve to a different row. Removes the replaced index entry. |
| Clear/delete retained row data in backing arrays | Unused entries could retain large fields/deltas. Clears vacated slots. |
| Customization and regex filters allocated excessively | Builds customized rows directly into the result and reuses a byte buffer for regex matching while preserving visible-column/join semantics. |
| CronJob writes remained enabled in read-only mode | Trigger/suspend bindings are dangerous and gated; callbacks recheck current read-only state. |
| CNPG plugin writes lacked dangerous flags | Backup, hibernation, interactive SQL, reload and restart are disabled in read-only mode. Namespace-view behavior is preserved. |
| Flux mutations lacked dangerous flags | Optional plugin mutations are disabled by k9s in read-only mode. |
| Flux trace could discover against another context | Both discovery and Flux execution receive the selected context and kubeconfig. Shell scripts receive values as positional arguments. |
| Flux ResourceSetInputProvider scope was wrong | Uses the actual plural resource name, enabling the correct action. |
| Shell pipelines could mask failures | Bash pipefail preserves failed Flux command exit status. |
| Cluster-scoped trace aborted on `namespaced: false` | Handles valid false without jq's truthiness exit failure, while rejecting malformed discovery. |
| Flux plugin shortcuts conflicted with built-in actions | Explicit overrides for intended native-action/sort replacements. |
| Synthetic resource browsers checked nonexistent Kubernetes resources | Namespace and empty-cache handling skip synthetic resource authorization/watch calls; constituent resources are still authorized normally. |

Independent review also caught accidental Edit/Delete and namespace-warp bindings on combined Flux rows. The synthetic resource declares an explicit empty verb set and removes namespace actions that require a concrete resource identifier.

## Measured table performance

Linux amd64, Go 1.27.1, `GOMAXPROCS=4`, 10,000 synthetic rows. These are microbenchmarks, not end-to-end UI latency measurements. Timings vary with load; allocation counts/bytes are the more reproducible comparison.

| Operation | Before | After |
| --- | --- | --- |
| Customize columns: bytes/op | 5,191,288 | about 1,797,847 |
| Regex filter: bytes/op | about 1,870,000 | about 585,600 |
| Regex filter: allocations/op | 20,060 | 60–61 |

The final repeated run, with other verification builds active, measured regex filtering at 8.99–10.21 ms/op and customization at 2.60–3.79 ms/op. No end-to-end speedup is claimed from these timings. Correctness tests cover matches spanning adjacent visible columns, hidden-column exclusion and inverse matching.

## Certificate diagnostics and shared UI follow-up

The follow-up adds native views for cert-manager Certificates, CertificateRequests, Issuers and ClusterIssuers, plus ACME Orders and Challenges. Certificate health combines controller conditions with reported expiration and renewal times, preserving expired status during renewal and rejecting stale health observations. Navigation follows explicit issuer/Secret references and owner UIDs; unavailable discovery, loading caches and denied child-list access remain visible. Certificate lists do not retrieve Secret data. See [certificate usage](certificates.md).

The optional cmctl plugin now confirms renewals, honors read-only mode and the selected connection, passes shell values positionally, and propagates command/pager failures. Regression tests execute substituted plugin scripts with stub commands.

The UI follow-up keeps the existing arrangement and skins:

- Shortcut descriptions share available width and truncate with an ellipsis so later shortcut columns remain visible.
- Breadcrumbs preserve word spacing and favor the current view when the path exceeds terminal width.
- Selection dialogs stay inside the viewport and retain keyboard selection for long lists.
- Shared table padding measures terminal display width for Unicode and tagged text. Flux/certificate controller text is escaped at presentation while raw data remains available for filtering and sorting.
- Flux STATUS sorting puts problems first; compact native views omit redundant KIND and long MESSAGE fields, while wide mode and the `i` status dialog retain details.
- Dynamically selected native renderers now supply their health colors to the browser, fixing the default-color fallback for native Flux and cert-manager views.

Independent review identified stale failed Issuing conditions bypassing generation checks and controller markup being interpreted as UI styling. Both received regression coverage and fixes. Simulated terminal tests cover narrow/wide resize behavior, literal tags, Unicode and long selection lists. Seven README screenshots show the running binary against a disposable local synthetic Kubernetes API; `scripts/capture-demo.py` reproduces them.

This adds resource-status diagnostics, not endpoint TLS probing or certificate-chain validation. No live cluster was used; real issuer/controller outcomes and environment-specific permissions still need an operator smoke test.

Follow-up verification passed on Go 1.25.8: `go test -count=1 -p 2 ./...`, configured golangci-lint 2.6.2 (zero issues), `go test -race -p 2 ./internal/certmanager ./internal/model1`, CLI build/version/help, all seven real-TUI demo captures and `git diff --check`.
